## 1. STORYTELLING (primary)

Break is the strongest section — the before/after pivot from "the source of the image was the artist" to "the source moved out into the world" is crisp, and the three-part consequence is well-marshalled. Afterlife resolves on the author→spectator reversal, which is the right closing note. The five sections are compelling, not listy or disjointed.

- **[FIX] Method, para 2 ("The ordinary part ends there").** Slightly soft transition; the phrase is doing connective work but reads as filler. Suggest tightening the opener to put Ernst's move first: *"The ordinary part ends there — and Ernst's real move was what he did after the rubbing."* Minor.

- **[NICE] Floorboards, para 4 + Method "A book, not the rubbings."** The 1925-vs-1926 distinction is made twice (floorboards para 4 foreshadows it; method delivers it). The repetition is deliberate and works as setup→payoff, but the floorboards teaser "the difference between them turns out to matter more than it sounds, as we will see" leans on a forward-reference (see CLARITY meta-narration finding). Keep the distinction, drop the wink.

- **[NICE] Break, three-part list.** "Three things follow, and together they are the break: First… Second… Third…" is the one passage that risks reading listy. It survives because each item is a full developed thought in prose, not a bullet. Acceptable as-is; no change required.

## 3. CLARITY + VOICE CONTRACT

### Meta-narration / reader-commands / forward-references

- **[FIX] Floorboards para 2 — "We will come to exactly how it works in a moment."** Meta-narration + forward-reference about the chapter's own structure. Cut. The frottage inline-define stands on its own without the promise. Suggest ending the parenthetical at *"…from the French frotter, 'to rub.'"*

- **[FIX] Floorboards para 4 — "two separate things… turns out to matter more than it sounds, as we will see."** Forward-reference / "as we will see" is meta-narration the voice contract flags. Suggest: *"Frottages 1925, portfolio 1926 — two separate things, and the difference matters more than it sounds."* (drop "as we will see").

- **[FIX] Method para 4 — "Now the distinction that matters for what you are actually looking at on this page."** Meta-narration (narrating the chapter's job) + mild reader-orientation. Suggest opening on the fact directly: *"There is one distinction that matters for what you are looking at. Histoire Naturelle is not the original rubbings."*

- **[FIX] Looking — section header "One sheet out of the thirty-four" + opener, and "the first thing to register is how quiet it is."** "the first thing to register" is a soft reader-command/meta-instruction. Suggest: *"…the look of pencil dragged over something grained, and it is strikingly quiet: no color, no hard outline…"*

- **[FIX] Break para 2 — "Three things follow, and together they are the break:"** Borderline meta-narration (announcing the structure). Defensible as a hinge, but the contract leans against narrating the section's own architecture. Optional: fold into prose — *"Three things follow from that move."*

- **[NICE] Looking "ground" para — "is exactly the effect Ernst was after. It makes you do the seeing."** and Break "The accident does the drawing." / factpack-echo "makes you do the seeing." Mild reader-address ("makes you do the seeing") used twice (looking + it's also in the factpack looking points). Reads as voice, not a command — keep, but don't add a third.

### Condescending glosses / honesty-labels

### Em-dash / &mdash; / literal "—" inside plain TS string fields  (VOICE-CONTRACT HARD FLAGS)

This is the one area with real defects. The const string fields (`hook`, `blurb`, `heroCredit`, `note`, `where`, `detail`, etc.) are **plain TS strings**, not JSX — a literal `—` is fine in a plain string (it renders as an em-dash), but `&mdash;`/`&ndash;` HTML entities do **NOT** decode in a plain TS string and would render as the literal text "&mdash;". Conversely the JSX prose (PART B) is the opposite: there `&mdash;`/`&ndash;` are correct and a literal `—` is also fine.

- **[BLOCKER if shipped as-is → downgrade to FIX (caught pre-wire)] PART A const string fields contain literal `—` (em-dash) and `’` etc. — these are CORRECT in plain TS strings.** Verified: `hook`, `blurb`s, `annotations[].detail`, `provenance[].note` use literal em-dashes and curly quotes. In a plain string field these render correctly. **No defect** — flagging explicitly because the gate asked to check for `&mdash;` misuse inside plain TS strings, and there is **none**: the const correctly uses literal `—`, not `&mdash;`. PASS.

- **[FIX] PART B JSX uses a mix of `&mdash;`/`&ndash;`/`&rsquo;`/`&ldquo;` entities AND literal `—` (em-dash) in the same prose.** Both render correctly in JSX, so this is cosmetic-consistency, not a render bug — but it is inconsistent. Two literal em-dashes appear in JSX strings where the surrounding style uses `&mdash;`: Floorboards para 3 (`He called it Histoire Naturelle &mdash; Natural History`) uses the entity, while Method para 3 list and others mix. Recommend the wirer pick ONE convention per file (entities throughout JSX is the existing house pattern in art-section-reader). Non-blocking; flag for the wirer.

- **[PASS] No literal "—" inside a *rendered* plain-string field that would mis-render.** Checked `hook`, all `blurb`, `heroCredit`, `stats`, `annotations`, `provenance`. All literal em-dashes are in plain-string contexts where they render as em-dashes. No `&mdash;` leaked into a plain string. Clean.
